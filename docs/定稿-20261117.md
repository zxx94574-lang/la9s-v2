## 一、全局原则（以后所有改动都按这个，写进 CLAUDE.md / 设计规范）

1. **简约但不简单（346）**：先判断整体要什么，不是说一处改一处、不把要求一股脑堆上去。每加一个功能先问：能不能用已有的四个底层做到——**筛选、分组、派任务 / 审批、档案联动**。能就不加新页面、新按钮。
2. **想全（举一反三的底层）**：改一处先想整条链——前后步、谁用（中方 / 员工 / 客户、电脑 / 手机）、价格可见性、账（应收 / 资金 / 毛利）、金蝶、库存、操作记录、异常和撤回、老数据、以后要不要调。
3. **设计有依据**：`docs/设计规范.md`（8 像素网格、格式塔分组、Fitts / Hick 定律、对比度、渐进展开、信息觅食），每次改界面过它的 8 条检查清单。
4. **亏钱 = 重中之重（344）**：不做亏钱的买卖；唯一例外是有「清仓决定」背书的清仓甩卖。
5. **异常一律直接拦（349）**，**非正常出库一律先审批**；**变动分两级（359）**：影响小 → 二次确认（黄）；影响大 → 二次确认 + 提醒中方（红色事件）。
6. **凡是还没定、以后可能改的规则 / 阈值 / 选项，都能在设置里调（350 / 354）**：一个单独的「规则参数 + 选项设置」界面是唯一来源，页面上用到的地方放小 ⚙ 跳过去（只中方）。
7. **金蝶是底线**：最终只对 编码 + 数量 + 金额（Q3）；系统可以比金蝶灵活（编码归一）。
8. **证据**：除报价确认外每一步都要照片 / 截图；**收款一律要付款凭证，现金也拍照**（旧「门店现金可不传」作废）。

## 三、订单流程（按步骤）

**报价 · 确认**
- 确认方式加「销售员确认」——**只用于这一步**（340）。
- 欠款客户下单 → 自动进中方审批，中方三选一（338）：① 直接放行 ② 先找货、卡出库 ③ 先不找货（单子停报价，客户不要了直接作废）；可「派人问付款计划」（结构化回填：哪天付多少 + 截图），计划存进客户档案，到期没付进紧急待办。
- 上次成交价 / 历史价格：307 应用流程（员工应用要中方批，中方直接生效；撤掉「没沿用就自动上报」，黄条改一行轻提示）、306 按钮挪进修改报价卡片、310 浅蓝描边 + 数字角标、309 全部总览复用订单总览表（并入 333 分组）；**上次成交价跳过整单折扣的单**，历史明细里折扣单标「整单折扣 −X」（357）。
- **整单折扣（357，取代 308 的单独一行）**：折扣金额按金额比例均摊进每个型号单价，取整，零头记抹零，应收正好等于谈好的数；照常走异价 / 会亏检查；金蝶直接用折后单价。

**找货 · 初检**
- 实际供货 ≠ 需求 → 必须写原因（快选 + 手写 + 翻译）（341）。

**销售订单 · 客户确认**
- 必须客户本人（或店员 / 收货人）确认，销售员确认不算（340）。

**复检打包**
- **必抽检（347）**：一行 数量 > 100 片、或 单价 > 5,000 XOF、或 总价 > 500,000 XOF（三个数可调）→ 必须选抽检结果才能完成；抽出问题必须写说明。

**出库**
- 表单分块（352）：① 发货（方式下拉、司机电话、Yango 截图）② 时间与收货（日期时间、收货人联系方式——下拉：客户本人 / 收货人 / 另给号码 / ＋新号码）③ 运费谁出 ④ 这次发多少 + 明细。收货人卡片显示在出库步，「用收货人信息」一键带入。
- **先出库、价格待定（Q8③）**：只中方，**必须先审批**才能确认出库；从出库起进紧急待办；签收照常确认数量，**价格没定卡在对账前**。
- 非正常出库（价格待定、欠款超限 / 超账期、有会亏的行、没成本、多发…）一律先审批（349）。

**签收**
- 签收 = 跟客户确认数量无误（313）：二选一「数量无误 / 有差异当场登记」；记「跟谁确认的」（姓名 + 电话 + 身份，v53 已做）；24 小时损坏规则（Q7，v53 已做）。

**对账**
- Balance 主数字 = 当前欠款（已定），按 353 骨架重排；逐笔流水按时间段（v53 已做）；退货算退货当月（333）。

**收款（314 / 317 / 318 / 356 / 358）**
- 表单三块：① 谁付的（日期、付款人）② 付了多少怎么付（**只选账户**——Cash-XOF / Wave-XOF / Cash-RMB / Cash-USD / 公司收款账户（再选 Wave / 银行），收款方式不再单独选；金额 + 币种；凭证必传）③ 钱在谁手里（交到公司 / 员工代收（只列在职员工）/ 在 Roland 手里）。
- 手续费：开关「我们承担」默认否；开了默认 1%（到账 99%），**高于 1% 红色确认 + 写原因，低于 1% 黄色确认**；差额记 Wave-XOF 办公费 → 中方确认。客户账永远按货款冲。**不用 Orange**（318 原文里的 Orange 删掉）。
- 公司收款账户（Roland）：跟客户核对后立刻冲客户欠款，流水记「未实际收到现金 · Roland 欠公司」；Roland 可分多次交回，差额 = 手续费；欠款板块直接看 Roland 欠多少 + 每一笔（客户、订单、金额、付款日、已交、还欠、压几天）；压款超 N 天进紧急待办。
- 收款金额 > 客户总欠款 → 二次确认「多出 X 记成预付」，多很多算影响大（359）。
- 撤掉出库后的「价格调整单」界面（357；355 作废；后端保留不删）。

**退货**
- 退货类型 / 具体原因改带搜索下拉，日期换统一日历（360）。

## 四、钱、价格、毛利

- **亏钱（344）**：事前——单价 < 到岸成本或整单毛利 < 0 → 不能下推，中方批 + 写原因（员工只看到「这行价格要中方批」）；事后——已出库毛利 < 0 → 紧急待办 + 亏损诊断（成本来源、成本是否含运费、成交价 / 档位价 / 成本、汇率、运费手续费退货各吃多少、最可能原因），中方必须选结论才能关；看板 / 毛利分析亏钱的置顶。
- **清仓（344 / 345）**：唯一允许亏的情况。物料定价里一张带日期的**清仓价表**：型号、清仓价、起止日期、适用对象（指定档位如 S / Wholesale，或指定客户）；没有清仓决定的亏本价一律拦；清仓亏损在毛利分析单独一栏。
- **审批三模式（345）**：每类决定在设置里选 自己定 / 知会 / 必须批准，并设谁批谁被知会；初始：清仓、改档位规则、核销坏账 = 必须汪波批准，其余自己定或知会；以后 Frank 可改成说一不二。送批自动生成**一页纸报告**，审批人可直接改（留痕）或退回，确认后立即执行。
- **汇率与定价工具（329 / 330）**：汇率设置填两个数——回款公司报价「1 万西法 = 多少人民币」（现 107.2）+ 公司美金汇率 6.7809，系统推出 1 美金 ≈ 632.5 西法；余量 5%（可调）；汇率变动提醒。**人民币定价工具（只给 S 级大客户）**：中方照箱单手填 人民币成本 / 每片运费 / 想要的利润，系统算出人民币价和西法价；成本以箱单人民币进价为准，金蝶美金价只用来核对（金蝶成本 = 进价 ÷ 6.7809 + 运费，**已含运费**，不要再加一次）。
- **毛利口径（333）**：按出库日期算；退货算退货当月（现在 margin_rows 是摊回原出库行，要改）。
