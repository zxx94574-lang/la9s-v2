# LA&9S 系统设计规范（2026-11-17 起，Frank：设计要有依据，不是只为满足要求）

每次改界面前对照本文件；每条规则写明「依据」，拿不准时按依据推，不按感觉。Frank 已定的 UI 偏好（CLAUDE.md §4）优先于本文件。

## 0. 风格方向（Frank 11-17 22:39 定）
- **飞书式清爽中性为主**：白底、细线、中等信息密度——员工天天用飞书，上手不用适应，适合整天看表格录单据。
- **借 Apple 式两样**：① 留白和字号层级更讲究（主数字更醒目、次要信息更淡）；② 给客户看的单据（报价单、销售单、Balance）做得更精致，代表公司形象。
- 不走金融终端式高密度（对本地员工和手机不友好）。

## 1. 版面与网格
- **8 像素网格**：间距只用 4 / 8 / 12 / 16 / 24 / 32 / 48。依据：Material Design、Apple HIG 的 8pt 网格——间距成比例，眼睛才觉得「整齐」。
- **左右平衡**：内容区不一边挤一边空；档案、详情一律两栏（左 = 对象自己的信息，右 = 我们定的 / 业务数据），窄于 900px 自动上下。依据：格式塔「对称」原则 + Frank 11-17 五五分。
- **阅读路线 F 形**：最重要的放左上（单号、客户、状态），操作按钮放右上或卡片底部右侧。依据：Nielsen Norman Group 眼动研究（F-pattern）。
- **一行文字 45–75 个字符**：说明文字最大宽度约 40em，超过就收进 ⓘ。依据：排版学经典行长（Bringhurst《The Elements of Typographic Style》）。
- **大屏限宽居中**：内容区最大约 1600px，两边留白。依据：同上，行太长视线换行会丢。

## 2. 分组与层级
- **相关的靠近、不相关的拉开**：同一组的字段间距 8px，组与组之间 24px，用留白分组而不是加线加框。依据：格式塔「接近」原则。
- **同一种东西长得一样**：所有档位一个 TierPill、所有状态一个浅底小块、所有链接一个蓝色下划线样式。依据：格式塔「相似」原则 + Jakob 定律（用户习惯从别处带来）。
- **层级最多三级**：页面标题 → 卡片标题 → 字段。字号阶梯 12 / 14 / 16 / 20 / 28，每级只用一种粗细。依据：模块化字号比例（约 1.25 倍）。
- **渐进展开**：默认只给要做决定的那几样信息，细节点开 / 悬停 / 长按再看（选单、通用型号、订单预览都按这个）。依据：渐进式呈现（Progressive Disclosure，NN/g）。

## 3. 操作与人体工学
- **点击目标**：电脑上按钮高 ≥ 32px，手机上 ≥ 44px，相邻按钮间距 ≥ 8px。依据：Apple HIG 44pt 触控目标 + Fitts 定律（目标越大越近越快点中）。
- **主操作只有一个**：一个卡片只有一个实心蓝按钮（保存 / 下推），其余用浅蓝描边；危险操作（作废、删除）红色描边、离主按钮远一点。依据：Fitts 定律反用（不该点的放远）+ Frank 310。
- **选项越少越快**：一组快选不超过 7 个，多了就分组或做成可搜索下拉。依据：Hick 定律（选项数越多决定越慢）。
- **能选就不打字**：日期用日历、单选用选项块、数字给默认值；原因 / 说明 = 快选 + 文字框。依据：减少记忆负担（Nielsen 十大可用性原则「识别优于回忆」）。
- **每个操作都有反馈**：点了 100ms 内有变化（按下态 / 提示条），超过 1 秒给进度。依据：Nielsen 响应时间三阈值（0.1 / 1 / 10 秒）。
- **出错前拦住**：必填项在按钮旁写「还差：…」，不等提交后才报错；不可撤销的操作二次确认（站内 Modal）。依据：Nielsen「防错」原则。

## 4. 颜色与可读性
- **只用三种颜色 + 状态色**（Frank 11-01）：品牌蓝 #0447b0、黑字、灰；状态红 / 黄 / 绿只用浅底小块。
- **对比度**：正文对比度 ≥ 4.5:1，灰色说明字不浅于 #6b7280。依据：WCAG 2.1 AA。
- **颜色不单独表意**：红黄绿旁边一定有文字或图标（「会亏」「−2.6%」）。依据：WCAG「不只靠颜色」，约 8% 男性有色弱。

## 5. 缩放与适配
- **任意宽度都正常**（Frank 11-17 底层规则）：弹层有最小宽度、不跟触发框走；放不下就换方向 / 贴满屏宽 / 整块换行；文字永远不竖排。验收 360 → 2560 每 40px 扫一遍。依据：响应式设计（Ethan Marcotte）「内容优先断点」。
- **手机**：一屏一件事，表格可左右滑但工具栏单行；弹层从底部升起；输入框 16px（iOS 不自动放大）。依据：Apple HIG、拇指热区（Steven Hoober 研究）。

## 6. 多页面联动
- **对象之间都能点过去**：型号 → 物料档案、客户 → 客户档案、员工 → 员工档案、单号 → 那张单、编码 / 入仓号 → 采购单。
- **带上「从哪来」**：目标页把和来源单据有关的行标「本单」排前面；档案永远是总览。
- **返回回到原处**：网址 + 滚动位置 + 打开的档案都还原。依据：信息觅食理论（Information Foraging，Pirolli & Card）——每一步都能闻到下一步的「气味」，用户才不迷路。

## 7. 改界面的检查清单（每次都过一遍）
1. 这一页最重要的三样东西是什么？是不是在左上、最显眼？
2. 有没有一边挤一边空？能不能两栏？
3. 同类东西样式一致吗（档位、状态、链接、按钮）？
4. 主按钮只有一个吗？危险按钮离它够远吗？
5. 点击目标够大吗（电脑 32 / 手机 44）？
6. 360 → 2560 扫过了吗？有没有竖排、超框、重叠？
7. 编码、单号、名字都能点吗？从别的页面进来时，「本单」标了吗？
8. 能选的有没有让人打字？要写原因的有没有快选？
