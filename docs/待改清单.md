## 2026-10-28 · 客户询单与报价

1. **添加机型不跳转**：点选机型添加后，页面不要自动滚到新增行；只弹轻提示「已添加：XXX」（1–2 秒消失）。选货框（种类按钮 + 搜索框）固定在原位，不随行数增加被推到下面。
2. **"要填的列"统一高亮（全站规则，Frank 10-28 两次提）**：每个界面里，当前这一步要填的那一列做成标记列——整列浅品牌蓝底 + 表头加粗加色 + 一个小铅笔图标；光标进到这一列时，整列边框亮一下（选中动画），让人一眼知道"现在在这一列操作"。其他只读列保持白底。各页面对应的填写列：
   - 报价：需求数量（+ 备注）
   - 找货：实际供货（少于预占时，差异原因这一格也跟着高亮，提示必填）
   - 销售订单：单价（只有中方能改，其他岗位不高亮）
   - 出库（分批）：本次出库数量
   - 收款（手动分配）：分配金额
   - 退货：本次退货数量
   做在表格组件里：凡是可编辑的列自动高亮，以后新页面不用再单独设置。
3. **表格画成实打实的格子（全站所有表格）**：像金蝶一样，横线、竖线都有，每个单元格边界清楚。
4. **批量粘贴 / 批量填数**：现在只能一格一格输。要像 Excel：
   - 从 Excel 或本表复制一列数字，点中起始格粘贴，自动往下填多行；
   - 选中一段单元格，一次填同一个数（例如全部 50），也可以用 Ctrl/⌘+D 把上一格往下填充。
5. **列宽可调**：表头分隔线可以左右拖动改宽度；双击分隔线按内容自动适应宽度。调过的宽度要记住。
6. **表头排序按钮（上下小箭头）**：点一下升序，再点降序，再点恢复。数字列按大小排（比如数量递增/递减），文字列按 A→Z / Z→A 排。
7. **表头筛选按钮（漏斗图标）**：按这一列的值做定向筛选。
   - 文字列选项（照金蝶）：包含、不包含、等于、不等于、以…开始、以…结束、为空、不为空，下面一个输入框。
   - 数字列（例如需求数量）建议另给一套：等于、不等于、大于、小于、介于（两个数）、为空、不为空。这样「要 50 片的有哪些型号」「50–100 片之间的有哪些型号」可以直接筛出来；只有文字式的「包含 50」会把 150、500 也筛进来。
   - 有筛选的列，表头图标要高亮，一眼能看出这张表现在是筛过的；合计行只算筛出来的行。

## 2026-10-28 · 补录需求 / 机型名称

8. **补录型号时打不出空格（bug）**：例如要填 `SS A05S`（SS = 三星，A05S = 机型）。原因：输入框每敲一个字就把首尾空格去掉，空格刚打出来就被删了。改法：输入时只转大写、不删空格；保存时才去掉首尾空格，中间多个空格合并成一个。
9. **机型名称统一调整（仅中方）**：中方的编辑权限更高。做一个「物料名称管理」：
   - 按关键词搜（例如 `A05`），型号、通用型号、未建档需求里所有含这个词的都列出来，可以再按种类筛；
   - 勾选后统一改名（例如 `SSA05S` → `SS A05S`），改前预览「将改哪些、改成什么」，确认后才生效，留改动记录；
   - 编码不变：订单都挂在编码上，改名后历史单据自动显示新名字，账不受影响；
   - 未建档需求里写法不同的同一型号（`SSA05S` / `SS A05S`），可以合并成一条，备货统计才准。
10. **品牌单独一列（Frank 10-28 定）**：物料加「品牌」列（三星 SS、ITEL、TECNO…），可按品牌筛选、统计。
    - 型号名称**保留品牌前缀**：不同品牌会撞型号（三星 A05 和 ITEL A05），库存里不会有光秃秃的 `A05`，只会有 `SS A05`、`ITEL A05`。
    - 搜索/识别时直接输型号就能找到（输 `A05` 两个都列出来，输 `SS A05` 只出三星）。
    - 品牌列由型号前缀自动带出，也可手动选；补录需求时同样先选种类，品牌可选可不选。

## 2026-10-28 · 订单工作流

13. **每一步都能回看，而且每一步有自己的"记录页"**：现在报价和热线确认共用一个页面，热线确认的内容（方式、备注、凭证）只出现在最下面的操作记录里；顶部流程条在窄屏下还要横向滚动，后面几步看不到。改成：
    - 流程条一屏放下（窄屏自动缩小字号或换两行），不出现横向滚动条；
    - 点任何一个已完成的步骤，都打开该步骤**只读的记录页**：报价单、热线确认（方式 + 备注 + 凭证）、找货单（找货人 + 照片 + 实际供货）、复核（谁、何时）、销售订单、客户确认（方式 + 凭证）、出库（方式、电话、地址、凭证）、收款明细；
    - 已下推的步骤**不能直接改**，页面上明确写「已下推，只读」。
14. **撤回下推（像金蝶反审核 / 删除下游单）**：要改前面的内容，必须在下一步点「撤回到上一步」，填原因（选项），系统把下游单作废并恢复上一步，才能重新修改、重新下推。规则：
    - 只能一步一步往回撤，从最新一步开始撤；
    - 撤回找货单 → 自动释放预占库存；撤回销售订单 → 回到"待出销售订单"；
    - **已出库的不能撤回**（账和库存已经动了），只能走退货；
    - 撤回需要主管或中方权限，每次撤回都进操作记录（谁、何时、原因）。
    - 需要在数据库里新增撤回函数并补测试（不是只改界面）。
15. **确认凭证（Frank 10-28 确认）**：凭证放在最有争议风险的那一步，不是每步都要。
    - **热线初步确认**（只是确认要不要货、要多少）：只点一个「确认方式」——WhatsApp 消息 / 电话 / 到店；截图**可选**，不强制。电话截图只能证明打过电话，证明不了客户同意了什么，强制传反而是负担。
    - **客户最终确认**（确认销售订单的数量和价格，之后就出库记账）：「确认方式」必选 + **截图必传**（例如客户在 WhatsApp 群里对销售单图片回复 OK 的截图）。以后出现"我没同意这个价格"的纠纷，靠的就是这一张。
    - 电话确认的客户最终确认：没有截图时，热线要在群里补发一句确认文字，再截那一句（让凭证落在文字上）。
16. **撤销误操作（Ctrl+Z / 顶部 ← → 按钮）**，分两层（Frank 10-28 提，Claude 补规则）：
    - **编辑层（还没下推的草稿、表格里的改动）**：像 Excel，⌘/Ctrl+Z 撤销、⌘/Ctrl+Shift+Z 重做，可以一直往回撤；页面顶部加「← 撤销」「重做 →」两个按钮，按钮旁显示要撤的是什么（例如「撤销：删除 BG6M LCD 行」）。误删一行、误改数量、误清空都能撤回来。
    - **业务层（已下推、出库、收款这类写进账里的动作）**：不能用 Ctrl+Z 直接抹掉——下一个人可能已经在用（仓库已开始找货、财务已发 Balance）。这类走第 14 条「撤回到上一步」：有原因、有记录、库存和账同步回滚；已出库的只能退货。
    - **删除一律是"作废"不是真删**：作废的单据进「已作废」列表，可以一键恢复；系统里不存在找不回来的删除。
17. **主管复核要"真复核"，不是点一下就过（Frank 10-28）**：复核没完成之前不能打包（系统已经卡住：没复核就出不了销售订单和出库）。复核页要有：
    - **复核人**：必选（默认当前登录的主管，可改）。
    - **复核照片**：必拍，手机点一下直接打开原相机，拍完自动压缩，不用另存、不用选文件；对手机配置要求低。
    - **复核数量列**（可编辑、按第 2 条高亮）：默认 = 找货员的实际供货；主管点数后发现不对就直接改，少了必须选原因（选项），多出来的预占自动释放。
    - **抽检**：主管不用每盒都拆。系统自动标出建议抽检的行（数量大的、金额高的、该找货员最近出过错的），每行一个「抽检」勾 + 结果选项：数量对 / 型号对 / 有问题；要了 10 盒抽 2–3 盒，勾选即可，不用手填。有「有问题」的行必须改数量或写原因，不能直接通过。
    - 数据库层：复核函数增加复核人、照片、复核数量、抽检记录，并补测试（不是只改界面）。

## 2026-10-28 · 销售订单

18. **改价偏差预警**（和档位价比，Frank 10-28）：
    - 偏差 ≥ 5%（高或低）：行内黄色提示「比档位价低/高 x%」。
    - 偏差 ≥ 10%：橙色预警，改价时要再点一次「确认这个价格」。
    - 偏差 ≥ 20%：红色重点警告，弹窗显示「档位价 → 新价、差额、整行金额变化」，必须选原因并二次确认；下推销售订单时再汇总提醒一次。
    - **单价为 0**：红色，下推时拦住，只有选了「赠品 / 样品」原因才放行。
    - 阈值（5% / 10% / 20%）放在设置里，只有中方能改。
    - 典型例子：BF7 BACK COVER 档位价 650，被改成 10（应该是输错了），按这个规则会被红色拦下。
19. **销售订单里改数量 / 改价要先"解锁"**（Frank 10-28）：
    - **出库前追加的新行**：加完就能直接改数量，不用解锁。
    - **之前已有的行**：默认锁住；要改数量或价格，先点该行「解锁修改」，选原因（客户改数量 / 客户不要了 / 录错了 / 价格谈判 / 其他，"其他"要写字），解锁后才能改；改完自动重新锁上，记录「谁、何时、从多少改成多少、原因」。
    - 客户「不要了」= 数量改为 0：释放预占，这一行进「未满足需求」的反向记录（客户取消），不算缺货。
    - 数据库：新增「改行数量」函数（带原因、同步调整预占），只能在出库前用；补测试。
20. **约定发货日期 + 到期提醒**（Frank 10-28）：
    - 客户确认时，除了确认方式，再选「发货日期」：今天 / 明天 / 指定日期（日历）。现在的「客户确认，明天发货」只是一句备注，系统不会记住日期。
    - 到了那天还没出库：铃铛和「我的待办」出现提醒「KONÉ TÉLÉCOM · BIZ-…-0007 今天该出库」，点一下直接打开这一单的出库页；过期没出的标红。
    - 出库页里如果要追加货：按第 19 条（新行直接改，旧行先解锁），价格按第 18 条预警；不追加就直接出库。
21. **步骤顺序：先发销售单图片，再客户确认**（Frank 10-28）：「客户确认」这一步的面板改成按顺序的两步——① 复制销售单图片（发客户群）/ 打印；② 客户确认（确认方式 + 截图必传，按第 15 条；+ 发货日期，按第 20 条）。没复制过图片也能确认（有时当面给客户看），但按钮顺序要体现先发后确认。
22. **销售单图片 / 打印**：版面按第 11 条（logo 左、单据名中、客户名和日期右上，币种只在金额里）；对齐按第 12 条（单价、金额右对齐，数量居中，其他左对齐）。

23. **「分批出库」防误触**（Frank 10-28：功能好，位置要防误触）：不用一个小勾选框。改成出库表格上方一个独立的带边框小板块，两个选项二选一：**整单出库（默认）｜分批出库**。

24. **发货失败 / 货被退回（不是客户退货）**（Frank 10-28）：Yango 到了说去不了；晚上叫车、员工急着下班先登记了出库；为了防查隔天才发、发出去又拉回来。处理规则：
    - **出库登记的时机**：Yango 司机真正把货拉走时再点「确认出库」（拍到司机/车辆的截图那一刻）。只是叫了车、约了明天的，先不登记，用第 20 条的「约定发货日期」挂着。
    - **登记后发货失败**：在出库记录上点「发货失败 / 退回」，选原因（Yango 去不了 / 客户改期 / 我方安排隔天发 / 其他），可拍照。系统自动：货按原仓位原库位回库并重新预占、客户总账冲回这笔出库金额、订单回到「待出库」、作废的出库单留痕不删除。之后重新约日期再发。
    - **限制**：只能在客户签收之前做；已签收的走正常退货（第 14 条规则：已出库只能退货，指的是客户收到之后）。
    - 如果财务已经把这笔的 Balance 发给客户，系统提示「Balance 需重发」。
    - 和客户退货分开：发货失败不进待检仓、不需要中方审批（货没离开我们的控制），但需要主管权限。
    - 数据库：新增「撤销出库」函数（冲回库存和应收、留痕），补测试。
25. **分批出库：每一批都是独立的一次发货**（Frank 10-28，含 2 个 bug）：

    - **Yango 截图自动识别**（下一版，Frank 之前提过）：上传 Yango 截图后自动读出司机名字、电话、时间填进去，人只核对。手动输入作为兜底。

    - 底部一行很淡的生成时间；颜色只用品牌蓝 + 红/绿表示欠款/预付。
    - 待 Frank 确认：客户看的单据（报价单、销售单、Balance）用**法语**还是**中法双语**？
28. **冲账方式精简为三种**（Frank 10-28）：① 冲最老的单（默认）② 指定冲这一单 / 这几单（按点选顺序，冲满一单再冲下一单，剩余记预付）③ 先不冲，记为预付款。**去掉「手动分配金额」**：它只在"一笔钱拆成指定金额分到几张单"时才用，实际极少；真遇到了，先记预付，再分别「冲到指定单」即可。

30. **跨币种收款的隐患和防护**（Frank 10-28 问）：
    - **汇率方向统一**：只允许一种写法「1 USD = ? XOF」「1 CNY = ? XOF」，杜绝把 600 写成 0.0017 这类方向错。
    - **汇率防手误**：显示参考汇率（上次用的 / 设置里的当日汇率），偏差超过 3% 黄色提醒、超过 10% 红色并要求二次确认。
